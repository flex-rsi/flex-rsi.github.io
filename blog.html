Can an agent improve the way it works?

Agent benchmarks usually fix the harness (the prompts, tools and control loop around the model) and score only the answer. Flex-RSI lets the agent rewrite its own harness between rounds. We ran 18 frontier models on 24 vision and robotics tasks, all from the same starting harness and with the same budget, and asked three questions: does self-improvement raise the score, on which tasks, and does editing the harness itself matter?

In short

Self-improvement usually works: 150 of 177 runs end with a higher validation score than they started with, by 10.4 points at the median. How much it helps depends on the task and on the model.

  1. 1It helps most when the agent builds the solution. When the agent writes a program or a robot policy, models start level and end far apart (0.9 → 38.8 points). When the solution is a single answer, they end about as far apart as they began (27.5 → 25.0).
  2. 2Pass/fail feedback stalls open-weight models. With a graded score, open-weight models improve too. When the evaluator reports only success or failure, they barely move (median gain 1.6 points) while closed models still climb (16.9).
  3. 3Open-weight models fall furthest behind on strict checks. Their outputs often look right but fail a simulator, an exact match or a physics test. There the gap to the best closed model reaches 50 points; where a judge or a tolerance scores, it can be as small as 0.1.
  4. 4Editing the harness helps. In six of seven pairs of otherwise identical runs, the run whose improver edits the harness scores higher. A weaker model given a stronger model's harness gains on only two of four tasks.

Setup

How a run works

Every model gets the same task, the same starting point and the same budget. Only the model differs.

  • Tasks. 24 tasks in five areas: Perception, Reasoning, Action (robotics), Reconstruction and Creation. The 20 main tasks each have at least six models.
  • Starting point. A starter solution and a general-purpose harness, the same for every model.
  • Data. Three disjoint splits. The development split, with labels, is the agent's to experiment on. The validation split is hidden and decides which new versions are kept. The test split is hidden too and scores the final solution once, after the run.
  • Budget. On a given task, every model has the same limits on time, GPU hours, tokens and rounds.

The harness has two parts that take turns in every round:

  1. The executor works on the solution: it edits code, runs experiments and evaluates on the development split.
  2. The new version is kept only if it scores higher on the validation split. Otherwise the run goes back to the previous one.
  3. The improver reads the round's transcript and scores, then edits the harness: the executor's prompts, tools and workflow, its own prompts, and the rule that decides when a new version is good enough.

The second part is what makes this recursive self-improvement: the agent changes not only its answer but the process that produces the next one.

Overall results

Claude Opus 5.5 ranks first, Gemini 4 Argon second

Claude Opus 5.5 is first with 91.6 and has the best test score on 11 of its 20 tasks. Gemini 4 Argon follows with 89.0. The best open-weight model, Qwen3.8-Flash-Next, places fifth.

Each task has its own metric, so we compare models by rank. On each task, a model scores the share of the other models it beats, from 0 (last) to 100 (first), and its overall score is the mean over the five areas. Gemini 4 Argon has run on nine tasks so far.

Finding 1

Self-improvement helps most when the agent builds the solution

On tasks where the agent builds a program or policy, models start 0.9 points apart and end 38.8 apart. On tasks with a single answer, they start 27.5 apart and end 25.0 apart: about where they began.

The tasks fall into two kinds.

  • The solution is a single answer (seven tasks). The starter passes each question to the model and returns its answer. These starters already score high (78.2 at the median), and the score depends on the model, so models are 27.5 points apart before the first round.
  • The agent builds the solution (thirteen tasks): a program, a robot policy or a processing pipeline. Every model starts from the same program, so on the nine of these scored on a scale the models start almost level.

On the first kind, the ranking at the end mostly reflects the base model. On the second, what each model builds during the run decides where it ends up.

Finding 2

Pass/fail feedback stalls open-weight models

On tasks where the agent builds the solution, open-weight runs gain 9.9 points with a graded score but only 1.6 with success or failure. Closed runs still gain 16.9 with success or failure.

Why should the kind of score matter? A new version is kept only if it raises the validation score. When the evaluator scores each episode on a scale, a change that improves part of an episode, such as a better grasp or a closer approach, already raises the score. When it records only success or failure, a change counts only once it turns a failed episode into a successful one. Until then, every attempt scores zero.

Closed models still manage that jump; open-weight models mostly do not. On RoboCasa, whose evaluator records only success, the median open-weight run gains 5.6 points and the median closed run 51.2. On 3D Tracking and Active Search, which are scored on a scale, open-weight runs gain about as much as closed ones.

Finding 3

Open-weight models fall furthest behind on strict checks

The gap between the best closed and the best open-weight model is largest where an output must pass a strict check (RoboCasa 50.0, ARC-AGI-2 49.2) and smallest where a judge or a tolerance scores it (Video Quality 0.1, Mass 0.8).

A strict check accepts an output only if it is actually right: the robot task succeeds in simulation, the output grid matches exactly, the level is cleared, or the reconstructed scene is physically and geometrically consistent. Open-weight models often produce outputs that look right but fail these checks.

The reconstruction tasks show this most clearly. On Scene from Video, the evaluator drops every reconstructed object into a physics simulator: for the open-weight models no object stays stable, while 70.7% of Claude Opus 5.5's do. On Scene from Photo, open-weight renderings resemble the photo (appearance score up to 81.8), but the furniture is not recovered as complete, correctly placed objects (object score at most 16.5, against 62.5 for both closed models).

Finding 4

Editing the harness helps

With the improver on, the test score is higher in six of seven pairs of otherwise identical runs, by 2.0 to 40.0 points. In the seventh, Claude Opus 5.5 reaches 80.0 both ways.

Does the improver matter, or does the executor do all the work? To find out, we ran pairs of runs that are identical (task version, budget, protocol and seed) except for one thing. In one run of each pair the improver never runs, so the starting harness stays frozen and only the executor works on the solution.

The improver helps most where the frozen harness makes little progress. DeepSeek-V4.1 Flash stays at 0.0 on Open Drawer without the improver and reaches 40.0 with it; Qwen3.8-Flash-Next goes from 21.0 to 59.3 on Active Search.

Can a weaker model borrow a stronger model's harness?

Only partly. A borrowed harness raised the weaker model's score on two of four tasks (by 20.0 points on Open Drawer and 1.4 on 3D Tracking), and in neither case did the weaker model come close to the stronger one.

  • Open Drawer. DeepSeek-V4.1 Flash, started from Gemini 4 Argon's final executor, reaches 20.0 if the executor stays frozen and 60.0 if Argon's final improver keeps editing it, against 40.0 when it improves its own harness from the start.
  • Turn On Sink Faucet. Qwen3.8-Flash-Next with Claude Opus 5.5's harness reaches 0.0 either way.
  • Active Search and 3D Tracking. Qwen3.8-27B, started from the stronger model's harness and improving it further itself, reaches 49.2 on Active Search (69.0 from the starting harness) and 53.8 on 3D Tracking (52.4).

Rounds and tokens

Most gains come early, and more tokens do not mean a higher score

The median improving run reaches 90% of its gain by round 3 or 4 in most areas. Token use and score are uncorrelated (rank correlation −0.05).

In Perception and Reasoning the median improving run reaches 90% of its gain by round 3, and in Creation by round 4. Action and Reconstruction, the two areas with the weakest starters, take until rounds 6 and 8: there the agent first has to build something that works before it can refine it.

The strongest models are also among the most economical. Claude Opus 5.5, GPT-6.1 Sol and GPT-6 Astra, three of the four highest-scoring models, use 0.35 to 0.61 times the median model's tokens on the same task. Five of the six open-weight models use at least the median, and all six score below 50.

Takeaways

What this means

Self-improvement is not one number. How much it helps depends on three properties of the task:

  • What the agent builds. On single-answer tasks the starter already does most of the work, and the ranking mostly reflects the base model. On tasks where the agent builds the solution, models that start from the same program end far apart.
  • How finely the evaluator reports progress. A graded score lets weaker models improve step by step; success or failure alone leaves them without a signal.
  • How strictly the output is checked. Outputs that look right are not enough where a simulator, an exact match or a physics test decides.

Across these tasks, the harness the agent writes for itself is part of why models end up where they do. Flex-RSI is an evolving benchmark: the leaderboard is updated as new runs finish, and new tasks, evaluators and results are welcome.
