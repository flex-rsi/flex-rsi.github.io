Tech reportNovember 2026Flex-RSI Team

Can an agent improve the way it works?

Agent benchmarks usually fix the harness (the prompts, tools and control loop around the model) and score only the answer. Flex-RSI lets the agent rewrite its own harness between rounds. We ran 18 frontier models on 24 vision and robotics tasks, all from the same starting harness and with the same budget, and asked three questions: does self-improvement raise the score, on which tasks, and does editing the harness itself matter?

In short

Self-improvement usually works. 150 of 177 runs end with a higher validation score than they started with. The median gain is 10.4 points. How much a run gains depends on the type of task and on the model.

  1. 1Building a program gains more than answering directly. On answer tasks, the model answers each question directly. The starter already scores high, so there is little room to improve. On build tasks, the agent builds a program or a robot policy. All models start from the same program, 0.9 points apart, and end 38.8 points apart.
  2. 2Sparse feedback stops open-weight models; dense feedback does not. Dense feedback gives a graded score for each episode. Sparse feedback gives only success or failure, like a sparse reward in RL. With dense feedback, open-weight runs gain 9.9 points. With sparse feedback, they gain only 1.6 points, while closed-model runs still gain 16.9.
  3. 3Open-weight models fall furthest behind on strict checks. A strict check accepts an output only if it is correct: a simulator, an exact match or a physics test decides. There, the best open-weight model is up to 50 points behind the best closed model. Where a judge or a tolerance decides, the gap can be as small as 0.1 points.
  4. 4Editing the harness helps. We compare pairs of runs that differ in one thing only: the improver edits the harness, or the harness stays frozen. The run with the improver scores higher in six of seven pairs. A weaker model that starts from a stronger model's harness scores higher on only two of four tasks.

Setup

How a run works

Every model gets the same task, the same starting point and the same budget. Only the model differs.

  • Tasks. 24 tasks in five areas: Perception, Reasoning, Action (robotics), Reconstruction and Creation. The 20 main tasks each have at least six models.
  • Starting point. A starter solution and a general-purpose harness, the same for every model.
  • Data. Three disjoint splits. The development split, with labels, is the agent's to experiment on. The validation split is hidden and decides which new versions are kept. The test split is hidden too and scores the final solution once, after the run.
  • Budget. On a given task, every model has the same limits on time, GPU hours, tokens and rounds.

The harness has two parts that take turns in every round:

  1. The executor works on the solution: it edits code, runs experiments and evaluates on the development split.
  2. The new version is kept only if it scores higher on the validation split. Otherwise the run goes back to the previous one.
  3. The improver reads the round's transcript and scores, then edits the harness: the executor's prompts, tools and workflow, its own prompts, and the rule that decides when a new version is good enough.

The second part is what makes this recursive self-improvement: the agent changes not only its answer but the process that produces the next one.

Overall results

Claude Opus 5.5 ranks first, Gemini 4 Argon second

Claude Opus 5.5 is first with 91.6 and has the best test score on 11 of its 20 tasks. Gemini 4 Argon follows with 89.0. The best open-weight model, Qwen3.8-Flash-Next, places fifth.

Each task has its own metric, so we compare models by rank. On each task, a model scores the share of the other models it beats, from 0 (last) to 100 (first), and its overall score is the mean over the five areas. Gemini 4 Argon has run on nine tasks so far.

Finding 1

Building a program gains more than answering directly

On build tasks, models start 0.9 points apart and end 38.8 points apart. On answer tasks, models start 27.5 points apart and end 25.0 points apart. Self-improvement separates the models on build tasks, but not on answer tasks.

We divide the 20 main tasks into two types by what the agent must produce:

  • Answer tasks (7 tasks). The model answers each question directly. The starter only passes the question to the model and returns the answer (on Kinematics and Mass, to a fixed open-weight model). The starter already scores 78.2 at the median, so there is little room to improve. The score depends on the model, so the models are 27.5 points apart before the first round.
  • Build tasks (13 tasks). The agent builds a program that produces the output, for example a robot policy or a processing pipeline. All models start from the same program. On the nine build tasks with a graded score, the models start only 0.9 points apart.

On answer tasks, the final ranking mostly shows how good the base model is. On build tasks, the final ranking shows what each model builds during the run.

Finding 2

Sparse feedback stops open-weight models; dense feedback does not

On build tasks with dense feedback, open-weight runs gain 9.9 points. With sparse feedback, they gain only 1.6 points. Closed-model runs still gain 16.9 points with sparse feedback.

We divide the 13 build tasks by the feedback that the evaluator gives:

  • Dense feedback (9 tasks). The evaluator gives each episode a graded score. Partial progress, for example a better grasp, raises the score.
  • Sparse feedback (4 tasks). The evaluator records only success or failure, like a sparse reward in reinforcement learning. Partial progress scores zero.

This difference matters because a new version is kept only if it raises the validation score. With dense feedback, each small step forward is kept. With sparse feedback, the agent sees no progress until a failed episode becomes a successful one.

Closed models still find a full success without the intermediate signal. Open-weight models mostly do not. On RoboCasa, which has sparse feedback, the median open-weight run gains 5.6 points and the median closed-model run gains 51.2 points. On 3D Tracking and Active Search, which have dense feedback, open-weight runs gain about as much as closed-model runs.

Finding 3

Open-weight models fall furthest behind on strict checks

The gap between the best closed model and the best open-weight model is largest on tasks with a strict check: 50.0 points on RoboCasa and 49.2 on ARC-AGI-2. It is smallest where a judge or a tolerance decides: 0.1 points on Video Quality and 0.8 on Mass.

We divide the tasks by how strictly the evaluator checks an output:

  • Strict check. The output must be correct. The robot task must succeed in simulation, the output grid must match exactly, the game level must be cleared, or the reconstructed scene must be physically and geometrically correct.
  • Judge or tolerance. A judge model scores the output, or the output must only be close to the reference.

Open-weight models often produce outputs that look correct but fail the strict check.

The two reconstruction tasks show this clearly:

  • Scene from Video. The evaluator drops each reconstructed object into a physics simulator. For the open-weight models, no object stays stable. For Claude Opus 5.5, 70.7% of the objects stay stable.
  • Scene from Photo. The open-weight renderings look like the photo (appearance score up to 81.8). But the furniture is not recovered as complete objects in the correct positions (object score at most 16.5, against 62.5 for both closed models).

Finding 4

Editing the harness helps

With the improver, the test score is higher in six of seven pairs of runs, by 2.0 to 40.0 points. In the seventh pair, Claude Opus 5.5 reaches 80.0 in both runs.

Is the improver necessary, or does the executor do all the work? To answer this, we ran pairs of runs. The two runs in a pair have the same task version, budget, protocol and seed. They differ in one thing only:

  • Self-improving harness. The improver edits the harness after each round, as in all other runs.
  • Frozen harness. The improver never runs. The starting harness does not change, and only the executor works on the solution.

The improver helps most when the frozen harness makes little progress. On Open Drawer, DeepSeek-V4.1 Flash scores 0.0 without the improver and 40.0 with it. On Active Search, Qwen3.8-Flash-Next goes from 21.0 to 59.3.

Can a weaker model use a stronger model's harness?

Only partly. The stronger model's harness raised the weaker model's score on two of four tasks: by 20.0 points on Open Drawer and by 1.4 points on 3D Tracking. On neither task did the weaker model come close to the stronger model.

  • Open Drawer. DeepSeek-V4.1 Flash starts from the final executor of Gemini 4 Argon. With a frozen executor, it reaches 20.0. When Argon's final improver keeps editing the executor, it reaches 60.0. When DeepSeek improves its own harness from the start, it reaches 40.0.
  • Turn On Sink Faucet. Qwen3.8-Flash-Next with the harness of Claude Opus 5.5 reaches 0.0 in both settings.
  • Active Search and 3D Tracking. Qwen3.8-27B starts from the stronger model's harness and then improves it. It reaches 49.2 on Active Search (69.0 from the starting harness) and 53.8 on 3D Tracking (52.4 from the starting harness).

Rounds and tokens

Most gains come early, and more tokens do not mean a higher score

The median improving run reaches 90% of its gain by round 3 or 4 in most areas. Token use and score are uncorrelated (rank correlation −0.05).

In Perception and Reasoning the median improving run reaches 90% of its gain by round 3, and in Creation by round 4. Action and Reconstruction, the two areas with the weakest starters, take until rounds 6 and 8: there the agent first has to build something that works before it can refine it.

The strongest models are also among the most economical. Claude Opus 5.5, GPT-6.1 Sol and GPT-6 Astra, three of the four highest-scoring models, use 0.35 to 0.61 times the median model's tokens on the same task. Five of the six open-weight models use at least the median, and all six score below 50.

Takeaways

What this means

Self-improvement is not one number. How much it helps depends on three properties of the task:

  • What the agent must produce. On answer tasks, the starter already does most of the work, and the ranking mostly shows the base model. On build tasks, models that start from the same program end far apart.
  • How dense the feedback is. A graded score lets weaker models improve step by step. Success or failure alone gives them no signal until they succeed.
  • How strictly the output is checked. An output that looks correct is not enough when a simulator, an exact match or a physics test decides.

Across these tasks, the harness the agent writes for itself is part of why models end up where they do. Flex-RSI is an evolving benchmark: the leaderboard is updated as new runs finish, and new tasks, evaluators and results are welcome.
